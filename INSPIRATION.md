# Card-specific inspiration

Checked 2026-10-09 against the repositories, source files, and live demos linked below. This is visual and interaction research for Pull Studio; it does not replace the renderer/export recommendation in [`RESEARCH.md`](./RESEARCH.md).

## Recommendation

Keep Pull Studio's direct Three.js card as the fidelity anchor: a thin extruded body with the uploaded front and back textures on their real faces, a real edge, and restrained lighting/shadow. This is the right foundation for a 360 inspection. With only front/back photographs, the unseen side surfaces should remain a neutral edge; a convincing full multi-angle surface requires the user to provide additional angle images.

Borrow the *ideas* below without copying source or card artwork:

1. Use BrannySG's face/edge separation as a visual reference for a card mesh and per-face material treatment, but do not copy its unlicensed code or bundled assets.
2. Borrow Pokebox's off-axis/parallax window and rarity-effect layering as optional presentation ideas. Drive every effect from Pull Studio's deterministic `sample(time)` so preview and export stay identical.
3. Treat Card-Studio's angle-ring interpolation as a future path only when a user supplies genuine multi-angle photos. Keep its cutout, generated background, and text/frame pipeline out of the default photo-preserving path.
4. Borrow the vocabulary of Simey's and cards-css's foil treatments—holo, rainbow, etched, cosmos—as references for subtle shader parameters. CSS tilt and blend modes are not a substitute for actual thickness or a back texture.

## Technique boundaries

- **CSS simulated tilt/foil:** Simey, cards-css, and the related [card-foil demo](https://sawyerwelden.com/card-foil/) change gradients, blends, filters, and DOM transforms. They are lightweight and expressive, but cannot reveal the true back or edge of a card. `sawyerWeld/card-foil` has no repository license detected, so it remains inspiration only.
- **Actual 3D scene:** Pokebox and BrannySG use Three.js geometry/cameras/shaders. Pokebox's card presentation is still largely layered planes; BrannySG is the closer thin-edge mesh reference, but is unlicensed.
- **Multi-view interpolation:** Card-Studio uses user-provided angle images and blends neighboring frames. It can preserve real photographed views when the input set is genuine, but its optional cutout/composition path can replace the original context and should not be silently applied to Pull Studio uploads.

## Fidelity guardrails

Preserve the uploaded pixels, source aspect ratio, and crop choice as the face texture. Lighting, shadow, edge thickness, and a low-opacity foil response may support the photograph; animated blend layers, generated backgrounds, perspective extraction, or synthetic text can change what the user uploaded. Keep manual crop/fit decisions explicit. A front-only upload can rotate through a neutral physical edge, while a supplied back image should be used as the actual back face. Any future multi-angle mode should make its required source views explicit and keep the sampled time/angle path deterministic.
