# Pull Studio renderer research

Checked 2026-10-09. This is a source review for a browser-first React/TypeScript/Vite prototype that preserves uploaded card artwork and exports one deterministic 8-second, 1080x1920 MP4. Repository metadata below comes from the live GitHub API or repository files on that date; README claims are separated from code and API evidence where useful.

## Recommendation

Build the renderer around direct Three.js and keep React for the controls and file UI. Put all scene motion in a pure function such as `sample(time, state)` and make preview and export call the same function before each render. Preview can use `requestAnimationFrame`; export can render fixed timestamps into the same 1080x1920 canvas. This avoids maintaining separate interactive and frame-renderer implementations and makes a single 8-second reveal reproducible.

Use Mediabunny's WebCodecs-backed `CanvasSource` and `Mp4OutputFormat` for the first export path. At 30 fps, export 240 frames with timestamps `i / 30` and duration `1 / 30`, await each `add()` for encoder/writer backpressure, then `await output.finalize()`. Probe `VideoEncoder.isConfigSupported()` for the chosen H.264 configuration first; WebCodecs is secure-context-only and still has incomplete browser coverage. A runtime probe should report an actionable export-unavailable state rather than silently producing a different format.

Use the uploaded image as the card's front texture, with explicit sRGB color-space handling and no image re-encoding or destructive preprocessing. The renderer should own only derived GPU textures and uniforms. A fixed export render target should be 1080x1920 at pixel ratio 1; preview can resize the CSS canvas while preserving the same scene coordinates.

## Practical export contract

1. Use one renderer and one `sample(t)` function. Clamp `t` to `[0, 8]`; do not read wall-clock time, random values, or React state during export. If procedural sparkles are used, use a fixed seed or hash of `(frame, cell)`.
2. Render preview at CSS size and export at exactly `1080 × 1920`, pixel ratio 1. The export loop should explicitly set camera aspect/projection and renderer drawing-buffer size rather than relying on the preview layout.
3. Validate the selected WebCodecs configuration with `VideoEncoder.isConfigSupported()`. H.264 in MP4 is the compatibility target, but codec availability is a runtime property and WebCodecs requires a secure context.
4. Create an `Output({ format: new Mp4OutputFormat(...), target: ... })`, add a `CanvasSource` using AVC/H.264, call `await output.start()`, then for each frame call `sample(i / fps)` → render → `await videoSource.add(i / fps, 1 / fps)`. Close the source and `await output.finalize()`; download the resulting buffer/blob.
5. Verify the result as a real 1080x1920 MP4 by reading its file metadata or opening it in a player. Also verify a few deterministic frame checkpoints (for example frame 0, the reveal peak, and frame 239) so preview and export can be compared.

## Source and asset caution

The BrannySG repository demonstrates the desired visual language well, but its GitHub API `license` is `null` and it has no `LICENSE` file at the main branch URL. Treat its code and included art as reference material until permission/provenance is clarified. Three.js, R3F, drei, and ffmpeg.wasm are MIT; Mediabunny is MPL-2.0; Remotion and GSAP have their own current terms. Uploaded Pull Studio artwork is separate user content and must remain untouched except for GPU texture upload/format conversion needed to render it.
